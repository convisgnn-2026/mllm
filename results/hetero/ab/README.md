## 해석

1. **라우팅만 바꿔도 최대 1.6×.** B(가중 2:1)는 프리필 중심에서 일관되게 1.43~1.46×, 혼합 n=200에서 1.61×. 회사 베이스라인(RR)이
   3090 속도에 묶여 4090을 놀리기 때문이다. 이 이득에는 분할·전송·새 인스턴스가 필요 없다 — **Router 층의 몫**.
2. **그 가중치의 정답은 워크로드·부하에 따라 다르다.** 같은 2:1이 디코드 중심 n=50에서는 A보다 4% 나쁘고(디코드 속도비 1.2~1.5×에는
   과한 편중), n≥100에서는 1.4× 좋다(3090 몫이 KV 용량 안에 들어가 선점을 피함). 고정 규칙으로는 못 맞추고 **계산해야 한다** — Solver 논거 ①.
3. **PD 분할(C)은 프리필 중심에서만 이긴다.** n=200에서 4.16 req/s 로 전 구성 최고(1.52×)이고, 부하가 클수록 좋아진다(3.59→4.00→4.16).
   같은 처리량인 B와 비교해 **TPOT p50 55 ms 대 87 ms** — 프리필이 디코드를 방해하지 않아 디코드 품질이 안정적이다. PD의 진짜 이득은 SLO 축.
4. **PD 분할은 디코드 중심에서 재앙이다.** C 0.13~0.25×, D 0.16~0.42×. 원인은 링크가 아니라 **KV 용량**: 모든 요청의 디코드 상태가
   한 장(약 35k 토큰)에 몰려 선점·재계산이 폭주한다(TPOT 200~400 ms). A·B는 두 장의 KV를 쓴다. 어제 LP 예측("순수 분할은 W1에서
   복제보다 나쁨")과 방향 일치, 크기는 LP가 못 본 선점 동역학 때문에 훨씬 크다. hetsim S3의 "PD 비용은 디코드 풀"과 같은 결론.
5. **방향이 뒤집힌다 (모델 검증).** 프리필 중심에서는 C(4090 프리필) ≫ D(3090 프리필, 3090 프리필 상한 2.3 req/s에 묶임).
   혼합 n=50에서는 D(1.58) ≫ C(0.81) — 디코드 일이 지배하면 빠른 4090을 디코더로 두는 편이 낫다.
   "프리필→4090 / 디코드→3090"이라는 규칙이 항상 맞지 않고, **워크로드에 따라 최적 배치가 반대**가 된다 — Solver 논거 ②.
6. **혼합은 간섭 비용이 있다.** A에서 혼합 n=50(36.7 s)이 순수 프리필(17.7)+순수 디코드(30.0)의 합보다 짧지만 각각보다 길다.
   긴 프리필이 디코드 스텝을 막고 긴 디코드가 꼬리를 끈다. 클래스별로 카드를 나누는 라우팅(E)이 다음 실험 후보.
7. **전송 병목은 별도 제약.** 1차 C 실행은 UCX 기본 TCP(0.5 GB/s)로 망가졌고, 튜닝(2.4 GB/s) 후에야 위 표가 나왔다.
   P2P 없는 이기종 카드 사이의 KV 전송 상한(8B 2K 기준 약 9 req/s)은 solver 의 링크 제약식에 그대로 들어간다.

## Motivation 에 쓸 수 있는 문장

> 같은 4090+3090 두 장, 같은 200개 요청에서 최선의 서빙 구성은 요청 구성에 따라 바뀐다: 프리필 중심이면 PD 분할(1.52×),
> 디코드 중심이면 가중 복제(1.37×, PD 는 0.16×), 혼합이면 부하량에 따라 가중 복제 또는 반대 방향 PD.
> 라운드로빈 대비 이득은 최대 1.6× 이지만, 잘못 고르면 0.13× 다. 어느 것도 고정 규칙으로 맞출 수 없고, 계산이 필요하다.

## 한계 (정직하게)

- 닫힌 투입(전부 t=0)이라 TTFT 는 큐 대기가 지배한다. 열린 도착(포아송)에서 SLO 달성률로 다시 재야 한다.
- 8B·24GB 두 장이라 KV 용량 효과가 극단적이다. 96GB PRO 6000 이나 268GB B300 에서는 4번 항목이 완화되거나 사라진다 — 규모 의존성 자체가 확정 18의 기여.
- 시드 1개, 합성 길이(고정). 데이터셋 분포와 시드 3개 반복이 필요하다.
- C 의 디코드 n=200 은 10분 상한으로 중단(결과 없음). D 디코드 n=200 은 651 s 에 완료.

## Goodput 재채점 (TPOT SLO, 2026-09-23) — `bench/hetero/score_goodput.py`, `goodput_T{50,75,100}.md`, `figs/fig5_*`

goodput(T) = TPOT ≤ T ms 인 요청 수 ÷ 총 완료 시간. 기존 requests.csv 재채점(새 실험 없음). TTFT 는 닫힌 투입에서 큐 대기가 지배해 미적용.

| SLO | 프리필 100%, n=200 | 혼합 75%, n=200 | 디코드 0%, n=100 |
|---|---|---|---|
| 처리량(무SLO) | B 3.99 · **C 4.16** · D 2.13 | **B 3.00** · C 1.03 · D 2.32 | **B 2.49** · C 0.23 · D 0.45 |
| TPOT ≤ 100 ms | B 2.93 · **C 4.16** · D 2.13 | B 2.29 · C 0.23 · **D 2.32** | **B 2.49** · C 0 · D 0.06 |
| TPOT ≤ 75 ms | B 0.64 · **C 4.16** · D 2.13 | B 1.12 · C 0.13 · **D 2.32** | **B 2.41** · C 0 · D 0 |
| TPOT ≤ 50 ms | B 0.30 · C 0.52 · **D 2.13** | B 0.51 · C 0.04 · **D 2.32** | **B 1.69** · C 0 · D 0 |

**읽기.** SLO 를 걸면 순위가 크게 바뀐다. (1) 프리필 100% 에서 C 는 SAR 100% 를 유지해 75 ms 에서 B 의 6.5× (4.16 대 0.64).
(2) 혼합 75% 에서는 **D 가 1위로 올라선다** — 4090 디코더가 TPOT 37~44 ms 를 유지(SAR 100%)하는 반면 B 는 프리필 간섭으로 TPOT 가
80~150 ms 로 퍼져 SLO 를 못 지킨다. 처리량 표에서 한 번도 1위가 아니던 D 가 SLO 축에서는 넓은 구간의 최선이 된다.
(3) 디코드 0% 에서는 여전히 B — PD 는 KV 용량 때문에 SLO 이전에 완료 자체가 느리다. (4) SLO 가 빡빡할수록(50 ms) 복제 구성은
거의 무너지고(B SAR 8~12%) PD 만 살아남는다. **목적함수(처리량 vs goodput)와 SLO 값이 최적 구성을 바꾼다** — 확정 15 의 로그 보존 덕에 재채점만으로 얻은 결과.
