여섯 항목 모두 동의하며, 추가 파일 읽기 없이 수정안만 정리합니다.

**동의와 보완**
1. Stage0 smoke → Stage1 파일럿 → Stage2 선택기 평가 순서에 동의합니다. 이전 답변의 run 수·시간·seed 수는 모두 가설값으로 표기하고, Stage1 결과를 본 뒤 Stage2 규모를 정합니다.
2. 동의합니다. Table IX와 Fig.1 수치가 "main on-demand + AO spot ≈ $0.909/h, CE = Θ/C, 배치 cap 미적용"과 일치한다는 것은 표 숫자로 재현되는 **가설**이며, solver 코드 확인 전에는 확정하지 않습니다. 예측 대상은 가용성, 비용은 가격모델의 계산값입니다. 통과하더라도 "GPU-시간·가정가격 기준 비용 개선"이며 실제 청구 절감이 아닙니다. 1,000요청당 비용은 서비스별 분배가 임의이므로 "mix λ 전체 기준 시간당 비용"만 1차 지표로 두고, 서비스별 분배는 보고하지 않거나 분배 규칙을 명시합니다.
3. 동의합니다. seed 0–4는 탐색에 이미 쓰였으므로 검증 plan은 새 seed로 새로 생성·실행합니다. 1차 중단판단에 쓴 seed를 held-out으로 재사용하지 않습니다. SLO 격자와 가격 격자는 실행 전 고정하고 전체 셀을 보고하며, 탐색으로 고른 셀을 primary로 소급하지 않습니다.
4. 동의합니다. backlog 기울기 단일 기준은 제거하고, 복수 관측창의 도착률·완료율·최종 in-flight와 seed 간 범위를 함께 보고합니다. 짧은 파일럿은 "안정성 미확정"으로 표시합니다. send_lag 50 ms, 오류 1%, 동일 oracle 90% 등은 최초 가정값으로만 기록하고 확정 기준으로 쓰지 않습니다. drain_timeout은 attainment 분모에 포함하되 HTTP 오류·과부하와 별도 열로 보존합니다.
5. 동의합니다. 단독·혼합 기반 선택이 일치하면 "고정배치 대비 가치 미입증"으로 보고하고, 선택 역전 외에 가용 영역 지도·불가 판정 정확도도 solver의 평가 항목으로 유지합니다. 단독 기준은 다른 서비스의 모델과 메모리가 상주한 **resident solo**로 통일합니다. 현재 LLM+DiT 하네스의 `none` 경로는 상대 모델을 로드하지 않으므로 Stage0에서 상주형 단독 경로를 추가해야 합니다.
6. 동의합니다. 3 서비스 동시 실행의 장비 요구는 현재 2 GPU에서 메모리·구현 적합성을 확인하기 전까지 미정으로 두고, LLM+DiT 우선은 진단용임을 명시하며 최종 scope는 LLM/VLM/DiT입니다.

**첫 단계(Stage0) 실행 순서와 산출물**
1. 후보 4개(S4_4090, S3_3090, S4_3090, S3_4090)를 같은 seed·같은 payload로 짧게 기동해 로드 성공, 메모리 점유, 요청 수십 건의 응답·오류를 확인합니다.
2. 상주형 단독 경로(LLM 요청만, DiT 요청만)가 같은 배치에서 동작하는지 확인합니다.
3. 계측 일치 검사: 모든 후보에서 plan·prompt hash, 계획 도착 기준 TTFT/E2E, 분모 규칙, 전력 샘플이 같은 형식으로 남는지 대조합니다.
4. 산출물: 후보별 `deployment.json`, `mem_after_load`, 요청 로그, 오류 목록, 상주형 단독 지원 여부, 3 서비스 동시 상주 메모리 추정치, Stage1 진행 가부 메모. 성능 수치는 보고하되 결론에 쓰지 않습니다.
