# 문제 정의 초안 — 이종 GPU 풀 멀티모달 서빙 solver

> 2026-09-21 세션에서 확정한 방향을 수식 한 장으로 고정한다. 새 solver의 사양서다.
> 논증은 `design.md`, 현황은 `handoff.md`. 이 문서와 어긋나는 서술은 이 문서가 우선한다.

---

## 0. 2026-09-21 결정 (이전 문서와 달라진 점)

| 항목 | 이전 (design.md) | 지금 |
|---|---|---|
| 이종 실험 장소 | B300 ↔ PRO 6000 노드 간 (IB 예정) | **4090 + 3090 한 서버.** 이종 IB는 없고 동기종만 설치. 데스크탑에서 카드별 프로파일을 뜨고 solver가 scale-up, 논문은 시뮬 외삽 |
| DiT 단계 분리 (T5→DiT→VAE) | 이종 노드를 건너는 레버 | **사장.** DiT는 통째 워커 테넌트. 레버는 카드 종류·장수만 |
| EPD | 단계 분리 일반 | **VLM 전용** (Encoder / Prefill / Decode) |
| 목적함수 | 테넌트 SLA 주, 집계 부 | **집계 goodput 최대.** 테넌트 희생 허용. 하한 α_t 는 선택 손잡이(기본 0) |
| solver / router 역할 | 둘이 모델을 공유, router 도 예측형 | **solver 가 전략·비용효율·배정 규칙까지 결정**, router 는 그 규칙을 실행 |

## 1. 입력

**하드웨어 풀 H (고정).** 카드 종류 k ∈ K, 각 n_k 장.
카드마다 (연산 C_k, HBM 용량 M_k, HBM 대역폭 BW_k, 시간당 단가 c_k).
링크: 같은 노드 안 PCIe, 노드 사이는 IB(동기종) 또는 이더넷(실측 23.5 Gbps). 링크 대역폭 BW_link.

**단가 c_k = 상각 + 전력.**
```
c_k [원/시간] = MSRP_k / (수명_년 × 8760)  +  TDP_k × 이용률 × 전기요금
```
클라우드의 시간당 VM 요금을 대신하는 자리다. 풀이 고정이면 총비용 Σ n_k c_k 는 상수이므로
CE = goodput / C 최대화는 goodput 최대화와 같다. c_k 가 답을 바꾸는 경우는 둘뿐이다:
(a) 카드를 끌 수 있을 때(전력), (b) 이종 카드의 GPU-초를 다르게 값 매길 때(4090 1초 ≠ 3090 1초).
논문에서는 (b)로 "비용 효율"을 정의한다.

**테넌트 T = {LLM, VLM, DiT}.** 테넌트 t 의 요청 클래스 c ∈ C_t:
LLM (S_in, S_out), VLM (이미지 수, S_in, S_out), DiT (해상도×프레임 템플릿).
창 w 의 클래스별 도착률 λ_{c,w}. SLO: LLM·VLM 은 (TTFT, TBT), DiT 는 E2E 마감(solo × slack).

---

## 2. 레버 (모두 남의 메커니즘)

| 테넌트 | 레버 ℓ | 역할 집합 | 출처 |
|---|---|---|---|
| LLM | colo, PD(p:d) | {P, D} 또는 {PD} | Splitwise, DistServe |
| LLM | + KV 파킹 (swap·prefix) | 위와 같음, 호스트 메모리 사용 | vLLM, LMCache |
| VLM | colo, PD, **EPD(e:p:d)** | {E, P, D} | EPD 분리 계열 |
| DiT | full | {W} | — |
| 공통 | 동거 패킹 | 한 카드에 두 역할, 몫 s_a + s_b ≤ 1 (실측 75/31) | MuxServe 류 |

기각: KV 스트리밍(FlexGen식) — 모델이 GPU에 들어가면 손해. AO — 범위 밖.

## 3. 결정 변수

```
x_{t,ℓ,ρ,k} ∈ ℤ≥0    테넌트 t, 레버 ℓ, 역할 ρ 에 배정된 카드 k 장수
r_t : C_t → (ℓ)       요청 클래스 → 인스턴스 그룹 (배정 규칙, router 가 실행)
σ_w = (x, r)          창 w 의 구성
```

이종의 핵심은 역할 ρ 와 카드 k 를 따로 고르는 것이다. 예: LLM 프리필 → 4090, 디코드 → 3090.
근거: 디코드는 대역폭에 묶이고 두 카드의 대역폭이 거의 같다(1,008 vs 936 GB/s). 미측정, 데스크탑에서 확인.

## 4. 성능 모델

```
(t, ℓ, ρ, k, 배치, 클래스)  →  단계 지연 T_ρ,  용량 μ
λ_{c}, 배정 x  →  SAR_c(σ)   (SLO 지킨 비율)
```

| 부분 | 근거 | 이종 확장 |
|---|---|---|
| LLM·VLM | LLMServingSim 2.0 표 (4090 검증 0.2~0.6%) | 카드별 회귀 T_real = β1_k · T_pred + β0_k (LLM-Pilot §IV-C) |
| DiT | `solver/sim.py` (B300 2%) | t_full 을 카드별로 재측정, 형태식은 유지 |
| EPD 인코더 | 가정 25 ms | ViT-L/336 실측 필요 |
| 동거 | 몫 75/31, 합산 1.05× | 4090에서 재측정 |

## 5. 제약

```
Σ_{t,ℓ,ρ} x_{t,ℓ,ρ,k} ≤ n_k                     ∀k      카드 수
가중치 + KV/활성 피크 ≤ M_k                        ∀ 인스턴스  메모리 실행가능성
λ_전송 × KV크기 ≤ BW_link                         PD 가 링크를 건널 때 (8B 2K 프롬프트: 초당 11건)
Σ 몫 ≤ 1                                          동거 카드
SAR_t(σ) ≥ α_t                                    선택, 기본 α_t = 0
```

---

## 6. 목적

**주 목적 — 작업가중 goodput.**
```
max_σ  Σ_c  w_c · λ_c · SAR_c(σ)          w_c = 클래스 c 요청 하나의 GPU-초 (측정: DiT 18.5, LLM 0.76, VLM 1.05)
```
고정 풀에서 "처리량"은 SLO 안에 처리한 일의 양이다. 요청 수로 세면 LLM 167건 = DiT 1건이라
DiT 가 항상 굶고, 이는 지표 왜곡이지 트레이드오프가 아니다. 작업가중은 GPU-초 기준이라 공정한 잣대다.
요청가중은 `--objective req` 로 병기한다.

**비용 효율.** CE = goodput / Σ_k c_k · (사용 카드 수). 카드 종류 가중을 넣을 때만 목적과 달라진다.

**시간축.** 창마다 σ_w 를 고르되, 역할이 바뀐 카드는 R = 33 s 비가용.
```
전환  iff  Σ_{h<H} [ gain(σ_new) − gain(σ_old) ]  >  reconfig_loss(σ_old → σ_new)
```
수요 예측은 "다음 창도 지금과 같다"로 충분하다(§15.11).

## 7. router 의 일

solver 가 낸 (x, r) 을 실행한다.
1. 요청 클래스 c 를 보고 r_t(c) 의 인스턴스 그룹으로 보낸다.
2. 그룹 안에서는 예측 완료 시각이 가장 이른 인스턴스를 고른다(같은 모델 사용).
3. 현업 라운드로빈이 베이스라인. 모델 판단은 전부 solver 에 있다.

## 9. 구축 순서 (한 단계씩, 앞 단계 결과로 회귀 검증)

1. **정수 분할 재현** — `cosolve.py` 의 84칸 표를 새 solver 가 그대로 낸다.
2. **레버 선택** — 인스턴스 그룹에 colo/PD/EPD/파킹을 변수로 추가. 기존 `pool*/` 스윕이 재료.
3. **이종 카드** — k 축 추가, 프로파일은 우선 비율 가정으로 넣고 데스크탑 실측으로 교체.
4. **시간축 통합** — `dynamic.py` 의 비용 인지 규칙을 새 solver 위에 올린다.
5. **router 골격** — (x, r) 을 읽어 요청을 배정하는 최소 구현. 회사 배포 대상.
