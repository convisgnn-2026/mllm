# 09/22 주간보고

## 1. 연구 방향 및 범위

- 대상: 사내 AI 플랫폼으로 유입되는 개별 LLM·VLM·DiT 추론 요청
- 목표: 고정된 온프레미스 이기종 자원에서 처리량 향상
- 접근: 요청 특성·가용 자원에 따른 단계 분리, 오프로딩, 장치 배치 선택
- 역할 구상: Solver의 구성·배치 판단, Router의 요청 배정·큐 제어
- 연구 범위: KV 캐시 오프로딩 포함, AO는 복잡도를 고려해 제외

| 워크로드 | 검토할 단계 분리 전략 |
| --- | --- |
| LLM | Prefill / Decode 분리 |
| VLM | Encode / Prefill / Decode 분리 |
| DiT | Text Encoder / Denoise / VAE 분리 |

## 2. 평가 방향 및 분석 항목

- 우선 지표: 동일 자원에서의 처리량 개선 여부
- 비용 효율성: 초기 실측 로그 확보 후 검토
- 핵심 분석: 한쪽 GPU의 유휴와 다른 쪽 큐의 대기가 동시에 발생하는 조건
- 혼합 요청: 단계 분리·오프로딩에 따른 병렬 처리 기회 및 유휴 감소 효과 확인

| 구분 | 측정·기록 항목 | 분석 목적 |
| --- | --- | --- |
| 처리량 | LLM·VLM tokens/s, DiT images/s, 혼합 요청 req/s | 동일 자원 대비 처리량 비교; 혼합 비율 고정 |
| 요청 성능 | 지연, 대기시간, SLO 달성 여부 | 처리량 증가에 따른 응답 성능 변화 확인 |
| 단계·전송 | 단계별 실행시간, 전송량, 전송시간 | 단계 분리 이득과 전송 부담 분석 |
| 자원 활용 | GPU 메모리 사용량, 점유·유휴 시간 | 메모리 제약 및 자원 활용 개선 원인 분석 |

## 3. 수학적 모델 및 규모 확장 계획

- 모델 입력: 단계별 연산량·메모리 요구량, 장치별 연산 성능·메모리 대역폭, 장치 간 전송 비용
- 선택 방향: 자원·워크로드 조건에 따라 유리한 분리·오프로딩·배치 전략 판단
- 확장 대상: PRO 6000 4장 노드, B300 8장 노드 및 더 큰 워크로드
- 확장 방식: 4090·3090 실측 기반의 성능 모델링 및 시뮬레이션
- 검토 조건: GPU 성능·메모리 용량, 워크로드 크기, 노드 간 링크 제약
- 연구 기여 후보: 규모 확장 시 최적 전략이 달라지는 조건과 처리량 개선 가능성 규명

## 4. 4090·3090 테스트 계획

- 실측 환경: RTX 4090 1장 + RTX 3090 1장
- 사전 측정: 장치별 단계 실행시간 및 GPU 간 전송 성능
- 워크로드 선정: 학술적 타당성을 갖춘 소규모 요청부터 순차 검증
- 시작 범위: LLM의 입력·출력 길이별 요청, DiT의 이미지 생성
- 메모리 대응: 24GB 범위에 맞춰 모델 크기·실험 조합 조정

| 비교 구성 | 실행 방식 | 확인할 내용 |
| --- | --- | --- |
| A. 복제 + 라운드로빈 | 두 GPU에 같은 모델 배치, 요청을 번갈아 배정 | 기본 처리량 및 큐·유휴 시간 불균형 |
| B. 복제 + 속도비 기반 배정 | 실측 처리 성능에 따라 배정 비율 조정 | A 대비 요청 배정 개선 효과 |
| C. 단계 분리 배치 | 단계 특성과 장치 성능에 따라 역할 분담 | B 대비 단계 분리의 추가 이득과 전송 비용 |
| D. 반대 방향 단계 배치 | C의 단계별 GPU 배치를 서로 교환 | 배치 방향에 따른 성능 차이 및 모델 예측 검증 |

- 비교 조건: 동일 모델·요청 집합·도착 조건 유지, 복제 가능한 모델부터 시작
- 혼합 실험: 메모리 내에서 실행 가능한 모델 배치를 기준으로 별도 비교
- 진행 순서: 단계·전송 측정 → 단일 워크로드 A~D 비교 → 혼합 요청 실험 → 규모 확장 시뮬레이션
- **우선 목표: 4090·3090의 동일한 고정 자원에서 유휴 시간을 줄이고 처리량을 높일 수 있는 요청·부하·배치 조건 확인**
