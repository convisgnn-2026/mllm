# LLM PILOT 확장 연구의 SLO와 비용 실험 인계

정리일: 2026-10-15. 사용자의 연구 목표는 LLM-PILOT을 LLM·VLM·DiT 공유 추론 환경으로 확장하고, 서비스별 SLO를 만족하는 분할 전략·단계 배치·자원 구성 중 비용 효율적인 구성을 선택하는 것이다. Claude는 실험 설계와 실행을 담당하고 Codex는 목적함수·비교 공정성·결과 해석을 검토한다. 이 문서의 제안은 성능 개선이 검증됐다는 의미가 아니다.

## 원 논문 전체 읽기 확인

- 원문: [LLM-PILOT PDF](../papers/refs/llm-pilot-ccgrid26.pdf), 암호화되지 않은 11쪽.
- 본문: [추출 텍스트](../papers/refs/llm-pilot-ccgrid26.txt). 초록, I 서론, II 배경, III 문제정의, IV 설계, V 평가, VI 결론, 감사의 글과 참고문헌 [1]–[31]까지 Codex가 읽었다. Fig. 1–3은 PDF 9–10쪽을 렌더링해 확인했다. 참고문헌에 인용된 외부 논문 전체를 읽었다는 뜻은 아니다.
- III-B, Eq. (7)–(8): 실시간은 TPS·TTFT·TBT 제약, 배치는 TPS 제약을 사용한다. V-A는 실시간 지연 평가로 평균 TTFT 및 배치 내 query 간 TBT p95를 명시한다. 현재 파일럿의 성공 요청 p90과 같은 정의로 간주하지 않는다.
- III-C, Eq. (9)–(10): `Theta = min(TPS, TPS_SLO)`, `CE = 3600 * Theta / C`, `C <= Cmax`. SLO 충족 후보에서는 Theta가 고정되므로 CE 최대화는 시간당 자원 비용 최소화와 같다.
- IV-B, Eq. (16): shared AO의 큐 대기를 이미 모델링한다. 차별점은 간섭의 최초 도입이 아니라 여러 종류의 서비스·단계가 공유하는 환경에서의 구성 선택과 예측 확장으로 검증해야 한다.
- IV-D와 V: 실행 불가능 후보 필터링, 보정된 성능 예측, 비용 최적화 및 실측 최선 선택과의 비교가 원 논문의 논리 구조다.

## 확장할 문제 정의 제안

서비스별 모델, 품질, 입력·출력 분포, 수요 벡터를 고정한다. 각 서비스의 지연·처리량·오류 관련 SLO를 만족하는 후보 중 시간당 비용을 최소화한다. 모달리티별 token/s와 image/s를 그대로 합산하지 않는다.

요청 단위 지연 SLO를 쓴다면 `P(T[s,m] <= D[s,m]) >= alpha[s,m]`를 서비스·지표별로 정의한다. 첫 응답과 생성 지연을 동시에 요구하는 경우 개별 충족률 외에 요청 단위 공동 충족률도 정의한다. 원 논문의 배치 지표에서 도착 과정과 꼬리 지연을 가진 지표로 확장하는 부분은 명시적인 설계 선택이다.

고정 GPU 두 장을 같은 시간 점유하면 자원 비용은 같다. 그러나 같은 서비스별 SLO·품질을 유지하며 더 많은 수요를 처리하면 비용당 처리능력은 개선될 수 있다. 따라서 그 범위에서도 SLO 충족 여부·예측·선택 손실과 함께 고정 비용의 최대 SLO 충족 수요를 주요 실측으로 평가할 수 있다. 같은 고정 수요의 시간당 비용 감소를 검증하려면 과금 자원의 종류나 수가 다른 후보가 필요하다. 유한 작업의 완료 비용은 실제 과금·점유시간까지 계산한다. 가정 가격·추정 복제 성능과 실측을 구분하고, 전력 절감과 임대 비용 절감도 별도로 보고한다.

고정 자원에서 모든 서비스의 수요를 동일 비율로 늘릴 때의 최대 SLO 충족 수요배율을 비용으로 나누어 평가할 수 있다. 이를 보조 목표로만 제한하지 않는다. 고정 mix의 처리능력/비용과 고정 수요의 최소 비용은 다른 목적함수이지만 함께 비용·처리능력 경계를 보여줄 수 있다. 자세한 근거는 [네 논문의 비용 비교](cost_efficiency_paper_comparison_20261015.md)에 정리했다.

## Claude에게 맡긴 첫 검토

로컬 Claude Code에 Read·Glob·Grep만 허용하여 원문 전체, 주요 그림, 연구 기록, 실행 스크립트 및 결과를 읽고 아래 내용을 제안하도록 요청했다. 최초 검토에서는 파일 수정이나 GPU 실험 실행을 허용하지 않았다.

1. 원 논문의 SLO·CE를 재구성하고 멀티모달 목적함수의 등가조건을 검토한다.
2. 실제 구현된 전략과 측정 가능한 장비 안에서 최소 실험 후보 공간을 정한다.
3. 같은 후보 공간의 고정 배치, 단독 성능 기반 선택, 혼합 성능 반영 선택, 실측 최선 구성을 비교한다. 실측 최선은 사후 기준점이며 실제 배포 가능한 예측 solver와 구분한다.
4. 탐색용 조건·seed와 검증용 조건·seed를 분리한다. 실측 승자를 보고 특정 SLO만 고르는 절차를 피한다. 실제 운영 SLO가 없으면 가정한 SLO와 민감도 분석임을 명시한다.
5. 동일 도착 계획·payload, 도착 기준 지연, 오류·미완료·timeout 처리, warmup·drain, 실행 순서 및 충분한 요청 수를 규정한다. 성공 요청의 p90만으로 전체 SLO 충족을 판정하지 않는다. 유한 drain 실험으로 정상상태 용량을 단정하지 않는다.
6. 실험 하나의 질문·구성·명령·필요 코드 변경·산출물·중단 기준을 제시한다. 단순 고정 배치가 충분하면 그 결론을 받아들인다.

## 논의 후 확정할 사항

- 서비스별 SLO는 운영 요구에서 받을지, 가정을 명시한 민감도 분석으로 평가할지.
- 가격·자원 후보는 실제 플랫폼 또는 클라우드 구성으로 정할지. 현재 장비 실측과 비용 모델의 역할을 구분할지.
- 첫 실험이 고정 자원의 SLO 충족 선택 검증인지, 다른 자원 구성까지 포함한 비용 최소화 검증인지.
- 논문 Eq. (9)의 단위와 Fig. 1·Table IX의 CE 표기에는 재계산이 필요한 부분이 있다. 원 수식에서 `TPS_SLO=100`, `C=0.46 USD/hour`이면 `3600*100/0.46`은 약 782,609 tokens/USD다. 본문의 CE=110과 차이가 있어 정규화·구현 정의를 확인해야 한다. 확장 연구에서는 수식·계산 코드·그림 단위를 일치시킨다.

### 합의한 평가와 실행 순서

평가는 두 축으로 진행한다. 첫째는 사전 고정한 서비스 수요 mix와 서비스별 SLO·attainment 목표를 만족하고 관측한 안정성 근거가 충분한 후보 중, 명시한 가격모델의 시간당 자원 비용을 최소화하는 것이다. 둘째는 고정 비용에서 mix 비율과 SLO·품질을 유지하며 감당하는 최대 공통 수요배율을 높이는 것이다. SLO scale·가격 비율의 사전 고정 민감도 범위를 함께 보고한다. 짧은 파일럿으로 정상상태 안정성을 확정하지 않는다.

1. Stage 0: 한 GPU에 두 서비스를 함께 놓는 후보와 두 GPU에 서비스별로 나누는 기본 후보의 로드·메모리·요청·계측을 확인한다. 다른 서비스 모델이 상주한 상태의 단독 요청 경로도 확인한다. 기존 P/D 분리 및 DiT 분할 후보는 구현 상태와 계측 호환성을 별도로 확인하고 다음 단계 후보에 포함할지 결정한다. 기능 확인 수치를 최종 성능 결론으로 사용하지 않는다.
2. Stage 1: 기능 확인을 통과한 후보의 작은 혼합 실행 파일럿을 수행한다. SLO와 가격 격자를 명시하고 전체 결과를 보고한다. 실제 비용 청구 자료가 없으므로 GPU 종류별 점유시간·전력과 가정 가격 기준 비용을 구분한다.
3. Stage 2: 탐색에 쓰지 않은 새 계획·seed를 고정하고, 동일 후보 공간에서 단독 기반 선택·혼합 성능 반영 선택·고정 배치·검증 실측 최선을 비교한다. 파일럿과 중단 판단에 사용한 데이터는 최종 검증 데이터로 재사용하지 않는다. 혼합 실측 lookup은 간섭 반영의 가치 검증용 기준선이며 최종 예측 solver의 기여와 구분한다.

성공 요청 p90 외에 오류·미완료를 포함한 요청별 공동 충족률, 도착/완료율, 복수 관측창의 backlog와 최종 in-flight를 보존한다. 원 논문 표의 cap·가격·정규화 방식은 구현을 확인하기 전까지 가설로 남긴다. 단독 기반 선택과 혼합 기반 선택이 같다면 현 범위에서 개선 가치 미입증으로 기록한다. 최종 연구 범위는 LLM·VLM·DiT를 유지하며, 세 서비스 동시 실행에 추가 장비가 반드시 필요한지는 아직 결정하지 않는다.
